# The PARA Method

> [!abstract] Overview
> PARA is a universal system for organizing digital information based entirely on **actionability** rather than topic. It eliminates the friction of deciding where a new note or file should go by running it through a four-step prioritization filter. 

The core philosophy is to minimize the time spent organizing and maximize time spent taking action. The system scales from a few files to thousands of notes, and should be mirrored exactly across all digital environments (Obsidian, Google Drive, local OS folders).

## The Actionability Hierarchy

Information is sorted from most actionable (top) to least actionable (bottom). 

### 1. [[Projects]]
Outcomes you are actively committed to that require multiple work sessions to complete.
- **Key Traits:** They have a specific, measurable goal AND a hard deadline or completion time frame.
- **Actionability:** High. Action-oriented and short-term in focus.
- **Examples:** `Write a blog post`, `Launch ASP.NET restaurant management system`, `Plan summer vacation`.
- **Obsidian Implementation:** Create a dedicated folder or Index Note for each active project. Tiago notes that having 15–25 active projects at once is standard. Once a project is completed, the entire folder/note is moved to Archives.

### 2. [[Areas]] (of Responsibility)
Roles or responsibilities that require a standard to be maintained over time.
- **Key Traits:** They are never "complete." There is no final goal to check off; they require ongoing maintenance. 
- **Actionability:** Medium. Important and relevant on an ongoing basis, but not necessarily screaming for immediate action today.
- **Examples:** `Health & Fitness (PPL tracking)`, `Finances`, `Software Engineering Career`, `Relationships`.
- **Obsidian Implementation:** Areas act as the permanent pillars of your life. Notes here might include workout tables, ongoing dietary logs, or long-term career planning.

### 3. [[Resources]]
Topics of ongoing interest or useful reference material waiting to be activated.
- **Key Traits:** A catch-all for information that doesn't fit into an active Project or a core Area, but might be useful in the future. 
- **Actionability:** Low. This is information gathered "just in case" or out of pure curiosity.
- **Examples:** `C# syntax snippets`, `UI/UX design principles`, `British pronunciation guides`, `Game recommendations`.
- **Obsidian Implementation:** This is the natural home for your Zettelkasten literature notes, web clippings, and general knowledge database. If a resource suddenly becomes actionable (e.g., you start a project based on a topic), the entire node or folder can be moved up to Projects.

### 4. [[Archives]]
Inactive items from the previous three categories safely tucked away in "cold storage."
- **Key Traits:** Almost completely unactionable, but preserved for searchability and future reference.
- **Actionability:** Zero. 
- **The Golden Rule:** Never delete anything. Moving inactive items to the Archives keeps your active workspace uncluttered while preserving your past work as a searchable "portfolio" or reference bank. 
- **Obsidian Implementation:** When a project ends, drag it here. This keeps your graph view clean and your daily processing fast, without losing the interconnected data.

---

## 🛠️ System Implementation Blueprint

To deploy this in your vault, Tiago recommends numbering the primary folders so they automatically sort by actionability rather than alphabetically:

- `1-Projects/`
- `2-Areas/`
- `3-Resources/`
- `4-Archives/`

> [!tip] The Workflow for New Notes
> When capturing a new concept, ask yourself in this exact order:
> 1. In which *Project* is this most useful right now? 
> 2. If no project, which *Area* of responsibility does this maintain?
> 3. If no area, which *Resource* topic does this belong to?
> 4. If none of the above, why are you saving it? (Or drop it in Archives).
